# Migration: `@noesis-edu/core` 0.2.0 → 0.3.0

**Status:** Release candidate (0.3.0-rc.0).
**Audience:** Downstream consumers — `noesis-eng`, `noesis-math`, `noesis-delf`,
`noesis-proof`, `open-source-logic-v1`, planned `knowledgetracker-v1`
integration.
**Companion docs:** `docs/architecture/UNIFICATION_ADR.md`,
`docs/architecture/PHASE_H_DIVERGENCE_LOG.md`,
`docs/architecture/PHASE_H_EXECUTION_PLAN.md`, `packages/core/CHANGELOG.md`.

## TL;DR

**0.3.0 is purely additive.** No removals, no behavior changes for any
public API that already shipped in 0.2.0. You can upgrade by bumping the
pinned version and adopting new modules at your own pace.

```diff
- "@noesis-edu/core": "0.2.0"
+ "@noesis-edu/core": "0.3.0-rc.0"
```

The interesting work is in **what you can now delete from your local
codebase** once you adopt the new modules — the verticals each carry
~3,000 LOC of duplicated engine code that core 0.3.0 absorbs.

## What did NOT change

- `BKTEngine`, `FSRSScheduler`, `SessionPlannerImpl` — same constructors,
  same methods, same outputs. Single-channel BKT consumers (`noesis-delf`,
  `noesis-proof`) see zero API change.
- `createNoesisCoreEngine` / `createDeterministicEngine` /
  `createSystemEngine` — same signatures. The new `overrides` field on
  `CoreEngineConfig` is optional.
- `getLearnerMetrics(engine, learnerId, atTime?)` — three-argument form
  still returns the original `LearnerMetrics` shape with the new fields
  undefined. The new `options?` fourth argument is the additive surface.
- `processEvent`, `replayEvents`, `exportState`, `importState` — all
  unchanged, including snapshot version (`1.3.0`) and backward-compat
  paths for pre-1.2 / pre-1.3 snapshots.
- `NoesisStateStore` interface and `InMemoryStateStore` impl are
  untouched. The new `OptimisticLockingStateStore` is a separate, richer
  interface for cases where silent overwrites are unacceptable.
- All event types (`PracticeEvent`, `DiagnosticEvent`, `TransferTestEvent`,
  `SessionEvent`, `ImplicitCreditEvent`, `CognitiveStateEvent`,
  `StageCompletedEvent`) — same shape.

## What's new

Twelve modules absorbed from the verticals. See `CHANGELOG.md` for the
full list with rationale; the migration-relevant pieces:

| New module | Replaces in vertical |
|---|---|
| `MultiChannelBKTEngine` | `bktService.ts` (per-channel state, drilling discount, grammar modifier) |
| `LayeredMasteryModel` | `masteryService.ts` (Learned/Mastered tiers + cooling-off + revocation) |
| `BudgetedSessionPlanner` | `plannerService.ts` (budget allocation + backlog control + skill-introduction caps) |
| `SessionLifecycleManager` | `sessionManagementService.ts` (createSession/getPlan/end + caches) |
| `PlannerSnapshot` | `plannerSnapshot.ts` (frozen inputs + replay function) |
| `OptimisticLockingStateStore` | retry-with-version pattern in `bktService.ts:325–428` and `sessionStateService.ts` |
| `SessionMetricsLogger` | `loggingService.ts` (`SessionAttemptTracker` + per-session metrics) |
| `FatigueDetector` | `fatigueDetector.ts` (only in `noesis-math` today) |
| `EloDifficultyCalibrator` | `difficultyCalibrator.ts` (only in `noesis-math` today) |
| `ItemHistoryAggregator` | `itemHistoryService.ts` (only in `noesis-eng` today; aggregation logic) |
| `AnswerNormalizer` + `LevenshteinMatcher` | universal portion of `answerService.ts` (only in `noesis-eng` today) |
| `EngineConfigOverrides` | `config.ts` per-pack tuning (everything pack-specific moves into a pack manifest's `EngineConfigOverrides`) |

## Per-vertical migration notes

### `noesis-delf`

You're the lightest migration — already ~95% on core. Two changes:

1. Bump `@noesis-edu/core` to `0.3.0-rc.0`.
2. (Optional) Move French normalization out of `engineService.ts` into a
   `@noesis-content/delf-fr` package implementing the new
   `AnswerNormalizer` interface. No core changes required to keep your
   current shape working.

That's it. All your existing `createNoesisCoreEngine` /
`getLearnerMetrics` / `createPracticeEvent` calls keep working unchanged.

### `noesis-math`

You contributed three modules upstream (`fatigueDetector`,
`difficultyCalibrator`, `difficultyService`) and reimplement the rest of
the engine locally. Migration:

1. Bump to `0.3.0-rc.0`.
2. Delete `src/lib/noesis/bktService.ts` → use `MultiChannelBKTEngine`
   from core. Pass math's two-channel set
   (`typed_answer`, `multiple_choice`) via the constructor's
   `MultiChannelBKTConfig`.
3. Delete `src/lib/noesis/fsrsService.ts` → use `FSRSScheduler` from core
   (already in 0.2.0). The math-specific response-time thresholds become
   `EngineConfigOverrides.responseTimeThresholdsMs`.
4. Delete `src/lib/noesis/masteryService.ts` → use `LayeredMasteryModel`.
   The math-specific "TYPED_ANSWER as primary" rule becomes a
   pack-supplied `SkillChannelMapping`.
5. Delete `src/lib/noesis/plannerService.ts` → use
   `BudgetedSessionPlanner`. Math's `defaultBudget=20` becomes a
   `SessionBudgetConfig` override.
6. Delete `src/lib/noesis/sessionStateService.ts` → use
   `OptimisticLockingStateStore` from core. Implement
   `OptimisticLockingStore<TKey, TValue>` against your Supabase rows.
7. Delete `src/lib/noesis/loggingService.ts` → use `SessionMetricsLogger`.
   The cross-vertical `recog_mc_*` column-name compat shim is a
   `noesis-app` schema-design decision (post-migration); for now keep
   your DB-write adapter local.
8. Delete `src/lib/noesis/fatigueDetector.ts`,
   `difficultyCalibrator.ts`, `difficultyService.ts` → use the core
   versions. Same defaults, same behavior; clock injection makes them
   replay-deterministic.
9. Move math-specific code (`generateMathItem`,
   `parseFraction`, `simplifyFraction`, math item types) into
   `@noesis-content/math-br`. Implement the new `AnswerNormalizer`
   interface for math-specific equivalence rules.

After migration, run `noesis-proof`'s equivalence framework against
your existing replay fixtures (`tests/phaseh/fixtures/`) to confirm
byte-for-byte behavior parity.

### `noesis-eng`

You contributed two patterns upstream (multi-channel BKT, layered
mastery) and have the most divergent local engine. Same shape as math
but ~3,200 LOC of services to delete. The
audit doc `noesis-eng/banjul/docs/PHASE_H_AUDIT.md` enumerates each
file and its disposition.

Specifically:

1. The 47 English contractions (`answerService.ts:75–123`) move to
   `@noesis-content/eng` as a pack-supplied
   `englishContractions: [string, string[]][]`.
2. The 25 grammar skill regex patterns (`config.ts:98–125`) move to
   `@noesis-content/eng`.
3. The grammar BKT modifier values (`pLearnMultiplier=0.85`,
   `pSlipAdd=0.03`) become a pack-supplied
   `EngineConfigOverrides.skillCategoryModifiers.grammar`.
4. The per-channel BKT priors and item-type → channel map become
   `EngineConfigOverrides.bktChannels` and
   `EngineConfigOverrides.itemTypeToChannel`.
5. Optimistic-lock `version` columns in `bkt_state` and `fsrs_state`
   (migrations 014/015) interface with the new
   `OptimisticLockingStateStore`. The `BKTConflictError` /
   `FSRSConflictError` semantics map onto the generic
   `OptimisticLockConflictError` (carrying `kind: "bkt" | "fsrs"`).
6. App-infra files (`answerOrchestrator.ts`, `preflightChecker.ts`,
   `exportCanonicalEvents.ts`, `dbWriteSurface.ts`) stay in
   `noesis-eng` for Phase H — they move to `noesis-app/` later under the
   broader `UNIFICATION_ADR.md` Phase 3.

### `noesis-proof`

You consume the engine; you don't reimplement it. Migration:

1. Bump to `0.3.0-rc.0`.
2. Use the new `MultiChannelBKTEngine.computeUpdate` static + the
   `PlannerSnapshot` types as adapter targets in your equivalence
   framework (`tools/phaseh-equivalence/`).
3. Run the framework against each vertical's
   `tests/phaseh/fixtures/` to certify Phase H-2/H-3/H-4 push-downs.

### `open-source-logic-v1`, `knowledgetracker-v1`

You consume `@noesis-edu/core` as a published artifact. Bump pinned
version. No code changes required — your existing usage is on the 0.2.0
single-channel surface, which is unchanged in 0.3.0.

## Adopting the new modules at your own pace

Every new module is opt-in. The recommended adoption order:

1. **Bump pinned version** — no other changes. Verify your tests still
   pass. (Should be a no-op modulo new bundled types in your IDE
   autocomplete.)
2. **Switch to `OptimisticLockingStateStore`** if you have a real
   concurrent-write race today (eng/math do; delf/proof don't).
3. **Switch to `MultiChannelBKTEngine`** if you have multiple assessment
   channels today (eng/math do).
4. **Switch to `LayeredMasteryModel`** alongside MCBKT — same module
   pair.
5. **Switch to `BudgetedSessionPlanner`** when you have allocation
   pressure (eng/math do; the small/single-channel verticals can keep
   `SessionPlannerImpl`).
6. **Switch to `SessionLifecycleManager`** when you want core to manage
   the in-flight session record + serialize/deserialize hooks.
7. **Switch to `SessionMetricsLogger`** for unified metrics computation.
8. **Switch to `EloDifficultyCalibrator`**, `FatigueDetector`,
   `ItemHistoryAggregator`, `AnswerNormalizer` as needed.

You can stop at step 1 if you have no immediate motivation; the surface
expands as you need it.

## Pack-package authors: use the contracts subpath

When building a `@noesis-content/<id>` pack package, import only types,
not the runtime:

```ts
import type {
  PackManifest,           // (TBD — pack manifest contract lives in app for now)
  ChannelId,
  EngineConfigOverrides,
  SkillChannelMapping,
  AnswerNormalizer,
} from '@noesis-edu/core/contracts';
```

This subpath emits zero runtime — your bundler tree-shakes the engine
away entirely.

## Risks

| Risk | Mitigation |
|---|---|
| Subtle behavioral divergence between vertical's `bktService.ts` and core's `MultiChannelBKTEngine` | Run noesis-proof's equivalence framework against your replay fixtures. The same magic numbers + same code path = same outputs. |
| `LayeredMasteryModel` cooling-off uses wall-clock comparisons | Always pass an injected `now: number`. Don't call `Date.now()` inline. |
| Per-vertical Supabase adapters need to plug into `OptimisticLockingStateStore` | Implement the interface against your `version` column. Single-retry-then-throw matches eng's existing semantics. |
| Cross-vertical column-name compat shim (math writing to `recog_mc_*` columns) | Per-decision: this is a `noesis-app` schema-design problem, deferred to post-migration. Keep your local DB-write adapter unchanged for Phase H. |

## When to drop the `-rc.0` suffix

Once all of the following land green:

- `noesis-delf` push-down PR merged.
- `noesis-math` push-down PR merged.
- `noesis-eng` push-down PR merged.
- `noesis-proof` equivalence framework certifies parity for all three.

We bump `0.3.0-rc.0` → `0.3.0`, the verticals re-pin, and `0.3.0-rc.0`
gets deprecated on npm.
