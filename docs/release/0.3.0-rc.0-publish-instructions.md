**Audience:** Edward (or whoever has the npm publish token on the VPS).
**Status:** Awaiting publish — PR #16 is open at https://github.com/Noesis-Edu/noesis-core/pull/16
**Estimated time:** 5 minutes.

## Pre-flight

Verify on your shell that `npm whoami` returns the `@noesis-edu` org publisher:

```bash
npm whoami
# Expected: an account that is a publisher on the @noesis-edu npm org.
# If wrong account: npm logout && npm login
```

## Steps

### 1. Pull the merged code

If PR #16 is **not yet merged**, stop and ask Chris to review/merge it.

If merged:

```bash
cd /path/to/noesis-core            # the VPS clone
git fetch origin
git checkout main
git pull --ff-only
```

If not merged but the publish is intentional from the feature branch (RC scenario):

```bash
git fetch origin
git checkout phase-h-1/core-0.3.0
git pull --ff-only
```

### 2. Confirm version + clean build

```bash
# From the noesis-core repo root:
node -p "require('./packages/core/package.json').version"
# Expected: 0.3.0-rc.0
```

If anything other than `0.3.0-rc.0`, stop and notify Chris.

```bash
npm install                         # if not already done on this clone
npm run build:core                  # tsc; outputs dist/
npm run test:core                   # 742 tests; must pass
npm run smoke:core                  # 6/6 smoke tests; must pass
npm run verify:core:pack            # dry-run npm pack; tarball reported
```

All four must succeed before publishing. If `test:core` or `smoke:core` fails: stop, notify Chris, do not publish.

### 3. Publish to npm with the `rc` dist-tag

```bash
cd packages/core
npm publish --access public --tag rc
```

**`--tag rc` is critical.** Without it, npm tags this release as `latest`, which would mean a default `npm install @noesis-edu/core` pulls the RC instead of stable 0.2.0. Vertical agents' lockfiles would silently shift to a release-candidate.

The `--tag rc` flag means:
- `npm install @noesis-edu/core@latest` → still pulls **0.2.0** (unchanged)
- `npm install @noesis-edu/core@rc` → pulls **0.3.0-rc.0**
- `npm install @noesis-edu/core@0.3.0-rc.0` → pulls **0.3.0-rc.0** (explicit)

### 4. Verify the publish

```bash
npm view @noesis-edu/core dist-tags
# Expected output:
# { latest: '0.2.0', rc: '0.3.0-rc.0' }

npm view @noesis-edu/core@0.3.0-rc.0 version
# Expected: 0.3.0-rc.0
```

### 5. Tag the git ref

```bash
cd /path/to/noesis-core/    # back to repo root
git tag -a v0.3.0-rc.0 -m "Phase H-1: pull-up to 0.3.0-rc.0"
git push origin v0.3.0-rc.0
```

### 6. Post-publish: notify

Ping Chris (and the vertical workspace agents if you have access to them) once the version shows in `npm view`.

## Recovery

If you publish the wrong version or the wrong tag:

```bash
# Move the rc tag to point at a different already-published version:
npm dist-tag add @noesis-edu/core@0.3.0-rc.0 rc

# Or unpublish the RC entirely (within 72 hours of publish per npm policy):
npm unpublish @noesis-edu/core@0.3.0-rc.0
```

Do **NOT** unpublish a release that anyone has already installed. Move forward with `0.3.0-rc.1` instead.

## When to drop the `-rc.0` suffix

After all three vertical push-downs (`noesis-eng/banjul`, `noesis-math/athens`,
`noesis-delf/denpasar-v1`) certify byte-identical replay-equivalence against
the new core via `noesis-proof/adelaide`'s framework, Chris will bump the
version to `0.3.0` (no `-rc`). At that point:

```bash
cd packages/core
npm publish --access public        # no --tag, defaults to "latest"
```

The verticals re-pin from `0.3.0-rc.0` to `0.3.0`, the `rc` dist-tag gets
deprecated, and the migration cycle closes.
